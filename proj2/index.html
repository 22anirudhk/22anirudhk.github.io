Section 1.1: Convolutions from Scratch

I implemented convolution directly from the summation definition using NumPy. Before sliding a kernel across the image, I add just enough zero padding so odd-sized filters (the 9×9 box filter here) keep the output the same size. Flipping the kernel vertically and horizontally turns the sliding operation into a true convolution instead of a cross-correlation.

The first version keeps four explicit loops—two for the image coordinates and two for the kernel taps. The second still visits every output pixel but hands the inner product to NumPy’s vectorized multiply-and-sum, which removes the innermost loops in Python. On the 9×9 box filter, the four-loop code takes about 36 s, the two-loop version about 5 s, and SciPy’s optimized convolve2d w/ boundary mode='same' and fill value 0 takes roughly 0.2 s. Comparing the results against SciPy shows that my padding reproduces its zero-boundary behavior.

Padding Helper I Made




def pad_image(img, filter_arr):
  img_rows, img_cols = img.shape

  filter_rows, filter_cols = filter_arr.shape[0], filter_arr.shape[1]

  # what shape of convolved image would be if we didn't do padding
  unpadded_convolved_img_rows = img_rows - filter_rows + 1
  unpadded_convolved_img_cols = img_cols - filter_cols + 1

  row_padding = img_rows - unpadded_convolved_img_rows
  col_padding = img_cols - unpadded_convolved_img_cols

  # padding s.t. only exact amt needed is added
  row_padding_top = row_padding // 2
  row_padding_bottom = row_padding - row_padding_top
  col_padding_left = col_padding // 2
  col_padding_right = col_padding - col_padding_left

  # crucial: use padded_img.shape throughout so you add right amt of padding based on current state of padded img
  padded_img = img
  if row_padding_top > 0:
      padded_img = np.concatenate((np.zeros((row_padding_top, padded_img.shape[1])), padded_img), axis=0)
  if row_padding_bottom > 0:
      padded_img = np.concatenate((padded_img, np.zeros((row_padding_bottom, padded_img.shape[1]))), axis=0)
  if col_padding_left > 0:
      padded_img = np.concatenate((np.zeros((padded_img.shape[0], col_padding_left)), padded_img), axis=1)
  if col_padding_right > 0:
      padded_img = np.concatenate((padded_img, np.zeros((padded_img.shape[0], col_padding_right))), axis=1)

  return padded_img

Four-Loop Convolution


def convolve_naive(img, filter_arr):
  # do padding
  img = pad_image(img, filter_arr)

  # CRUCIAL: FLIP FILTER first horizontally then vertically
  filter_arr = np.flip(filter_arr, axis=0)
  filter_arr = np.flip(filter_arr, axis=1)

  out_rows = img.shape[0] - filter_arr.shape[0] + 1
  out_cols = img.shape[1] - filter_arr.shape[1] + 1
  out = np.zeros((out_rows, out_cols))

  filter_rows, filter_cols = filter_arr.shape[0], filter_arr.shape[1]
  num_filter_pix = filter_rows * filter_cols

  for img_start_r in range(out_rows):
      for img_start_c in range(out_cols):
          # get part of image that is overlapped with the filter
          overlapped_img = img[img_start_r : img_start_r +filter_rows, img_start_c : img_start_c+filter_cols]

          assert overlapped_img.shape == filter_arr.shape

          overlap_sum = 0
          
          for filter_r in range(filter_arr.shape[0]):
              for filter_c in range(filter_arr.shape[1]):
                  overlap_sum += overlapped_img[filter_r][filter_c] * filter_arr[filter_r, filter_c]
              
          # now do average of the sum. this is what will be written out for this pixel
          value = int(overlap_sum)

          out[img_start_r][img_start_c] = value

  return out

Two-Loop Convolution



def convolve_faster(img, filter_arr):
  # do padding
  img = pad_image(img, filter_arr)

  filter_arr = np.flip(filter_arr, axis=0)
  filter_arr = np.flip(filter_arr, axis=1)

  out_rows = img.shape[0] - filter_arr.shape[0] + 1
  out_cols = img.shape[1] - filter_arr.shape[1] + 1
  out = np.zeros((out_rows, out_cols))

  filter_rows, filter_cols = filter_arr.shape[0], filter_arr.shape[1]
  num_filter_pix = filter_rows * filter_cols

  for img_start_r in range(out_rows):
      for img_start_c in range(out_cols):
          # get part of image that is overlapped with the filter
          overlapped_img = img[img_start_r : img_start_r +filter_rows, img_start_c : img_start_c+filter_cols]

          assert overlapped_img.shape == filter_arr.shape            

          multiplied_img = np.multiply(overlapped_img, filter_arr)
              
          # now do average of the sum. this is what will be written out for this pixel
          value = int(np.sum(multiplied_img))

          out[img_start_r][img_start_c] = value

  return out

Section 1.2: Gradient Magnitude & Edge Detection (Finite Difference Operator)

I reuse the faster convolution approach to filter the cameraman image with the finite-difference operators D_x = [1, 0, -1] and D_y = [1, 0, -1]^T. Keeping everything in floating point lets me square, sum, and take sqrt(dx**2 + dy**2) without losing sign information; only when saving do I rescale the arrays into the 0–255 display range.

These tiny three-tap filters act like slope meters: a constant patch gives near-zero response, while an intensity jump produces a large positive or negative value. D_x is tuned to left-right changes, so it lights up vertical edges where the image differs across columns; D_y does the same for top-bottom differences, revealing horizontal edges. Combining the horizontal and vertical responses therefore highlights places where brightness changes abruptly.

To produce a binary edge map, I swept thresholds and chose 30—it keeps the tripod, horizon, and coat edges while suppressing high-frequency sensor noise in the sky.

Section 1.3: Derivative of Gaussian (DoG) Filter

I build the 2D Gaussian blur by generating a 1D kernel with cv2.getGaussianKernel and taking its outer product with itself. For σ = 1.4 the kernel size is 9×9. Convolving cameraman with this blur before computing gradients reuses the Part 1.2 pipeline but with much less noise.

Intuitively, the Gaussian is a weighted average that suppresses tiny pixel-to-pixel glitches while leaving broader structures intact, so the derivative sees clean ramps instead of spiky noise. Building the DoG filters goes one step further: smoothing and differentiation merge into a single kernel, guaranteeing the same noiseless derivative no matter which order we apply them.

I also differentiate the Gaussian itself: convolving the 9×9 kernel with D_x and D_y yields the DoG filters shown below. Filtering cameraman with these derivative-of-Gaussian kernels produces gradients that line up with the blur-then-differentiate approach.

Similar to part 1.2, I swept a few candidate thresholds and settled on 30 for the binarized gradient magnitude image; it strips away most of the residual noise while still hanging onto some horizon edges I want to highlight.

Section 2.1: Image Sharpening (Unsharp Masking)

I rewrote unsharp masking as a single convolution: begin with the scale filter that is zero everywhere except for a center value of 1 + α, subtract α times the Gaussian blur (σ = 2, 13×13 kernel), and treat that difference as one unsharp filter. Convolving each color channel with this combined filter simultaneously adds back the amplified high frequencies while preserving the low-pass component; my helper then writes out the blurred image, the high-frequency layer, and the sharpened result after clipping into the display range.

Another way to view it: the blur is a soft-focus version that holds the coarse shapes, so subtracting it extracts just the wiggles and edges our eyes interpret as detail. Scaling that high-frequency layer and adding it back exaggerates local contrast without rewriting the underlying low-frequency lighting, which matches the spec’s derivation of unsharp masking as “original + boosted detail.”

The Taj and waterfall examples show α ∈ {1, 3, 5}. Increasing α strengthens fine edges but quickly exaggerates them if alpha becomes too large. Blurring the waterfall first demonstrates the limit: adding back high frequencies cannot recover detail that low-pass filtering already removed.

Section 2.2: Hybrid Images

Each hybrid starts by bringing the two RGB images into rough alignment (my own pairs are pre-cropped to the same size beforehand). I work in floating point, blur the “far” image with σ = 5 using a 31×31 Gaussian kernel to keep only its low frequencies, subtract that same 31×31 blur from the “close” image to isolate high frequencies, and average the two bands before converting back to an 8-bit image for saving. Empirically (trial error multiple times), σ = 5 struck the cleanest balance between suppressing noise and preserving the recognizable outlines I wanted.

The Gaussian blur acts like the retinal averaging that happens when we stand farther away or shrink an image: small details smear together, leaving just the low-frequency silhouette that still reads correctly at a distance. High-frequency edges survive only when we view the hybrid up close, so stealing them from the “close” subject forces our brain to recognize that subject when the pixels are large in our field of view. Mixing those two filtered bands therefore gives the expected flip: near distances are dominated by the sharp details, while far distances emphasize the smooth structure of the blurred image, matching the spec’s description of how perception switches with viewing distance.

Cat↔Derek is the required reference; Dog↔Muffin and Happy↔Angry are my additional pairs; Me↔Federer includes the full workflow: aligned inputs, filtered components, and Fourier log-magnitude plots that show the low frequencies of Federer and the high frequencies of me dominating where expected. All examples use σ = 5 (31×31 kernel) for both blur steps.

Section 2.3: Multi-Resolution Blending (Gaussian/Laplacian Pyramids)

I build Gaussian stacks by repeatedly blurring each RGB channel (σ = 5, 31×31 kernel) and collecting the results without downsampling. The Laplacian stack is the difference between neighboring Gaussian levels, with the coarsest Gaussian added at the end so that summing the stack reconstructs the original image in floating point.

Thinking in frequency bands helps: the shallow Laplacian levels carry crisp detail, while deeper levels describe only slow intensity changes. When we blend each band separately, the fine-scale seams stay confined to the levels that actually contain those frequencies, so the blurred mask can gently hand off ownership from one image to the other without creating a step.

For the apple-orange and cow↔horse blends I start from the classic half-bright, half-dark vertical mask, which recreates the paper’s straight cut before the pyramid smooths it. The eye↔me example swaps in the hand-drawn elliptical mask so the transplant fades softly around the eyelids.

During blending, every Laplacian level is combined as mask · A + (1-mask) · B, and the mask itself is blurred at each level with the same σ = 5, 31×31 Gaussian to feather the seam. The Apple↔Orange visualizations document the required Gaussian and Laplacian stacks, while the cow↔horse and eye↔me blends provide the two additional examples (one of them uses an irregular ellipse mask to taper the transplant smoothly).

Most Important Thing I Learned

By far, the most important thing I learned was the importance of knowing when to clip images in [0, 255], normalize images, and cast images to uint8. There were many instances of me doing the wrong combination of these operations, leading to unexpected blown out or darkened portions of the images. A related learning was to be cognizant of the fact that often transformations done purely for visualization should not affect downstream steps that may need the full range of data.
